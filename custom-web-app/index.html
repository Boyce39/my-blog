01 / START WITH ONE COMPLETE FLOW

先讓一個流程真正完成。

01

收資料與檔案

釐清必填欄位、檔案格式、大小與用途。資料保存成功才顯示完成，失敗時保留輸入，避免使用者不知道有沒有送到。

02

訂單與內部處理

定義待確認、處理中與完成等狀態，以及誰能變更。避免把提交需求誤認為付款成功或店家已接受訂單。

03

API 與自動化串接

先確認服務是否有可用 API、授權與費用，再規劃資料同步與通知。第三方故障要有重試、防重複與人工接手方式。

02 / LIMITS ARE PART OF THE DESIGN

先確認限制，才不會做完才發現不能用。

01

功能需求，不等於立即能上線

金流、簡訊、LINE 與硬體設備可能需要業者申請、合約或實機。依外部依賴分段驗證，未開通就不宣稱已支援。

02

權限、個資與備份

公開資料與管理資料分開，密鑰留在伺服器。依專案確認登入、紀錄、資料保存與復原需求，不把敏感資料塞進前端。

03

小範圍上線，再決定擴充

先選一個有用且能驗收的流程，記錄實際操作問題。確認有人用、真的省下工作，再做下一階段，不預設需要大型平台。

03 / WORK, NOT EMPTY PROMISES

不只給你作品網址，也說明為什麼這樣做。

從影像服務與咖啡店的不同情境，了解資訊怎麼安排、操作怎麼銜接，以及哪些功能需要分階段完成。

01

FepPhoto｜影像服務入口↗

服務與價目、門市資訊、線上下單與檔案提交入口。看如何把資訊與下一步接在一起。

02

Pixel364｜咖啡店操作流程↗

菜單、選項、價格與店家確認狀態。從手機介面看功能網站的規劃方式。

BEFORE WE START

合作前，先講清楚。

費用怎麼算？有固定套餐嗎？

先確認頁面、內容、功能、資料流與維護責任，再提供書面範圍與報價。網域、第三方服務、付款手續費與後續維護分開說明；預算選項不是對外售價。

會保證 Google 第一名或一定增加訂單嗎？

不會。會把可讀內容、手機操作、搜尋基本設定與詢問路徑做好，但排名與成交受市場、內容、預算及營運影響。以實際曝光、有效詢問與報價結果逐步調整，不用虛構數字作保證。

上線後資料與網站能交接嗎？

在開工前約定帳號歸屬、程式與素材授權、資料匯出、操作教學及維護邊界。涉及客戶個資或交易時，另確認權限、備份與保存方式，不把安全責任留到最後。
