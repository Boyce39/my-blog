01 / CHOOSE BY THE PROBLEM

從你要解決的問題選，不用先懂技術。

01

公司與品牌網站↗

服務散在社群、舊站手機難讀、客戶不清楚你能做什麼？先整理內容、信任資訊與詢問入口。

02

預約與詢價流程↗

反覆確認服務、時間、規格與檔案？讓客戶先提供必要資訊，也讓待確認與已成立不再混在一起。

03

客製功能與自動化↗

訂單、會員、資料處理與 API 串接。先驗證一個關鍵流程，再逐步擴充，不為了做系統而做系統。

02 / WORK, NOT EMPTY PROMISES

不只給你作品網址，也說明為什麼這樣做。

兩個開發案例，不把功能清單當成成效數字，也不公開內部營運資訊。

01

FepPhoto｜影像服務入口↗

服務與價目、門市資訊、線上下單與檔案提交入口。看如何把資訊與下一步接在一起。

02

Pixel364｜咖啡店操作流程↗

菜單、選項、價格與店家確認狀態。從手機介面看功能網站的規劃方式。

03 / HOW WE WORK

先把合作講清楚，再開始製作。

01

01｜釐清與取捨

確認客戶、操作情境、必要功能與現有資源。先定義最小可用範圍，不一次堆滿所有想法。

02

02｜書面範圍與分段驗收

確認交付物、修改次數、驗收條件、費用與時程後再開工。例外狀態與手機操作也算驗收，不只看截圖。

03

03｜上線、交接與後續

整理帳號與資料歸屬、操作說明、備份與維護範圍。追加功能另確認，不把一次交付變成無限期免費維護。

04 / BEFORE YOU REQUEST A QUOTE

準備詢價前，先看這兩篇。

01

網站費用怎麼抓？↗

把內容、功能、維護與第三方費用拆開，比較不同報價時才不會只看頁數。

02

有流量，為什麼沒詢問？↗

檢查搜尋意圖、服務說明、信任依據與表單，而不是只靠增加特效。

BEFORE WE START

合作前，先講清楚。

費用怎麼算？有固定套餐嗎？

先確認頁面、內容、功能、資料流與維護責任，再提供書面範圍與報價。網域、第三方服務、付款手續費與後續維護分開說明；預算選項不是對外售價。

會保證 Google 第一名或一定增加訂單嗎？

不會。會把可讀內容、手機操作、搜尋基本設定與詢問路徑做好，但排名與成交受市場、內容、預算及營運影響。以實際曝光、有效詢問與報價結果逐步調整，不用虛構數字作保證。

上線後資料與網站能交接嗎？

在開工前約定帳號歸屬、程式與素材授權、資料匯出、操作教學及維護邊界。涉及客戶個資或交易時，另確認權限、備份與保存方式，不把安全責任留到最後。
