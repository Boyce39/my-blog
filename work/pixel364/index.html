BOYCELAB / DEVELOPMENT CASE / PIXEL364

Pixel364：把咖啡店的選擇，整理成手機上的流程。

巷樹珈琲的網站開發案例。重點不是堆滿技術名詞，而是讓菜單、選項、價格與下一步保持一致，也把顧客介面與店家需要確認的狀態分開。

免費取得 3 點改善建議↗已有需求，討論專案 →

先釐清問題，再確認範圍與報價。不需要先購買方案。

● HUMAN-CENTERED SYSTEMS

讓每一步，都有下一步。

  1. 01找到你的服務SEARCH / CONTENT
  2. 02看懂你能解決什麼SERVICE / PROOF
  3. 03順利詢問或完成操作INQUIRY / WORKFLOW
先讓人看得懂，再讓系統跑得順。

查看公開網站 ↗以下介紹開發情境與設計取捨，不代表營收成效或所有整合均已完成。公開功能以目前網站為準。

01 / MENU → OPTIONS → CONFIRMATION

選擇可以很多，操作不能混亂。

01

從手機開始整理菜單

把品項、選項與價格放在操作能理解的位置。小螢幕不應該因為資訊很多，就讓按鈕或確認內容被遮住。

02

桌位與取餐情境分開

桌位 QR、外帶與訂位需求涉及不同資訊，規劃時分開處理，不把所有情境擠成一個長表單。

03

送出與接受訂單不同

顧客操作、伺服器記錄、店家確認與付款結果分開驗證。畫面不能只因為按了按鈕，就假裝整個交易已經成立。

02 / DEVELOPMENT BOUNDARIES

功能規劃與已串接項目，分開說明。

01

先測流程，再談完整自動化

硬體出單、退款與部分付款整合屬分階段開發範圍，不能只看顧客頁面就宣稱全部營運功能已完成。

02

適合借鑑的部分

適合用來討論多選項、價格計算、手機操作與狀態確認；不是用不存在的餐廳營收成果，替新專案作保證。

BEFORE WE START

合作前，先講清楚。

費用怎麼算？有固定套餐嗎？

先確認頁面、內容、功能、資料流與維護責任，再提供書面範圍與報價。網域、第三方服務、付款手續費與後續維護分開說明；預算選項不是對外售價。

會保證 Google 第一名或一定增加訂單嗎？

不會。會把可讀內容、手機操作、搜尋基本設定與詢問路徑做好，但排名與成交受市場、內容、預算及營運影響。以實際曝光、有效詢問與報價結果逐步調整，不用虛構數字作保證。

上線後資料與網站能交接嗎？

在開工前約定帳號歸屬、程式與素材授權、資料匯出、操作教學及維護邊界。涉及客戶個資或交易時，另確認權限、備份與保存方式，不把安全責任留到最後。
